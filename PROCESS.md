# Process overview

It's clear the future of software development is inexorably tied to optimising your application of Large Language Models. This concept has heavily influenced my process, through planning, implementation, and testing.

## 1. Planning

The player should feel like they are steering a great interstellar entity, shaping the solar system in cooperation or competition with everyone else.

I thus developed the core design documents, starting with high level goals which informed the game design in [`game-design.md`](docs/game-design.md) (mechanics and user interaction) [7549419](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/7549419), with each major mechanic justified in a game design [ADR](docs/adr/) (G1 to G6). That in turn informed the system design in [`system-design.md`](docs/system-design.md) (system-level requirements) [8745d21](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/8745d21), likewise justified by the system design [ADRs](docs/adr/) (S1 to S4), where S4 makes the case for the stack against the requirements in S1 to S3. Having separate documents at different levels of granularity helps manage context and alignment when working with LLMs and subagents. 

## 2. The updated harness

My earlier `execute_plan` skill, that created atomic steps before delegating to fresh subagents, turned out to be too restrictive for Opus 5.5 and actually made the software worse. 

Instead I had Opus derive its own, looser build process from it, with a plan in `build-process.md` that sets objective exit criteria for each stage instead of a task list [297a6cf](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/297a6cf), and a ledger in `progress.md` to track development against the goals. The plan was aligned to the crit calendar to make sure the work was completed on time [e65ad45](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/e65ad45). `CLAUDE.md` serves as an index for everything important, including the brief, the ground-truth documents in reading order, and the standing rules [99716d6](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/99716d6). 

To replace `execute_plan` I designed `comp4020_resume`, which reads the ledger and continues from wherever the last session stopped, so a single command resumes the build from any point [b0cbb23](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/b0cbb23). Committing as you go also had to become an explicit rule, after I found the agent was batching work [d0ab0c0](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/d0ab0c0).

## 3. Human in the loop

Because the scope of the game is fairly large, designing every detail before building it was infeasible, so I went down the rapid iterative prototyping route instead. 

This meant that every so often results weren't what I wanted, purely because I hadn't defined it earlier. The UI was the clearest case, with the first client a set of panels and tables, when I wanted Stellaris-style visuals as the main interface [8b7f4ae](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/8b7f4ae). I wrote that rule into `CLAUDE.md` and all three design documents so later sessions couldn't drift back [604d19c](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/604d19c). A human was clearly still needed in the loop, so to make this more seamless I designed `comp4020_update`, which takes my idea dumps and integrates them as changes into the core documents that `comp4020_resume` then reads [fa42c7c](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/fa42c7c). The loop became;
1. I braindump a change with `comp4020-update`
2. Claude turns my braindump into changes in the core documents and harness 
3. I run `comp4020-resume` to keep building 
4. I playtest on completion, and if needed go back to Step 1.

## 4. Integrating feedback

The crit 8 feedback suggested the game was quite addictive, but I'd been so focused on the mechanics and visuals that I'd neglected playability, as feedback centred on a clearer UI, instructions on what to do next / how to play, and more visual feedback. 

I added those requests into the design documents [89b4079](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/89b4079), and Opus built the icons, a selection panel without tabs, the Empire menu and an in-game Guide with very little input from me [fe12709](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/fe12709), [670b52e](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/670b52e), [0bde927](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/0bde927), [2eb3063](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/2eb3063). It also made me realise that because the mechanics aren't entirely simple, I'd need to playtest thoroughly with simulated players (lightweight agents, essentially) against measurable goals, to make sure enough happens in a short time for players to get hooked and actually experience every mechanic. So I started putting the headless sim to work against concrete pacing targets, such as a first colony within five to eight minutes.

## 5. Formalising design decisions

Once the base game was built, I needed to balance a number of variables (like resource count, war scaling, build time) which required explicit decisions behind balance changes. 

The source was `game-design.md` and `system-design.md`, whose fourteen sections each describe a designed goal deserving its own ADR. My first attempt didn't go well, with Claude slopping out 23 ADRs in one commit [ed1adb6](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/ed1adb6), describing decisions without arguing for them, providing strawman alternatives and "the author's reasoning" written in my voice. I threw those away and scaffolded one record per design section [6c3ec78](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/6c3ec78), but twenty-eight records still split single ideas across several files, so I consolidated them into six game design and four system design ADRs, each tied to one goal in the README, and drafted them with Claude one at a time, giving feedback on each before moving to the next [40b5325](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/40b5325). Its drafts kept falling back on the same habits (internal goal codes like "P3" that mean nothing to a reader, phrases like "the chain starves" that give abstract things agency, tidy "not X but Y" flourishes), so rather than correcting each draft, I wrote those into `CLAUDE.md` as writing rules for every document. I also had Claude write a [PRFAQ](docs/prfaq-claude-draft.md) [198a224](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/198a224) and score the remaining work with RICE. Its main criticism was that the game targets 24 nations over half an hour, while a marker plays with two people for ten minutes. However, the game is designed for a group of friends, over ten minutes to ten weeks, not two markers. The thirty minute targets just ensure every mechanic is reachable in a short session. Beyond that, it mostly reaffirmed my own idea of the game.

## 6. Workflows and simulated testing

Because the rules are a pure module shared by the server, client and sim, I could simulate playthroughs rapidly, which made automated balancing realistic. 

Six seeded bot archetypes (e.g. conqueror, trader, researcher) rerun after every change to the game's numbers, measuring twelve targets from colony timing to every strategy winning a fair share of stages [c295e53](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/c295e53). Alongside them, `/playtest` has six Haiku players and a Sonnet analyst, which play a live server after each build [7398baa](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/7398baa). A loop rule keeps this finite, acting only on broken targets or confusion two players share. Each recommended balance change is small and targeted, logged in [docs/balance-log.md](docs/balance-log.md). Over eight loops this solved real issues, like a starved early game [379d005](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/379d005), interface problems [ed404bb](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/ed404bb), [209c664](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/209c664), [2e58944](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/2e58944), and lower income for conqueror-inclined playstyles resulting in the "plundering" mechanic [41f93a7](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/41f93a7), [10916a2](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/10916a2). When a UI change silently broke eight end-to-end tests, the fix went into `CLAUDE.md` as a rule rather than a retry [fd07958](https://github.com/comp4020-agentic-coding-studio/comp4020-final-drvcarroll/commit/fd07958). All up, it cost roughly $30 for possibly hours of human work.
